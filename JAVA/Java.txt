24. Inherintance is OOP feature in java that allows one class to acquire properties and methods of another class.
    The class that provides properties is called parent/super/base class.
    The class that inherits properties is called child/sub/derived class.

25. Why we use Inherintance ? 
    a) code reusability
    b) method overriding 
    c) supports run tiime polymorphism 

26. Types of inheritance - 
    a) Single inheritance - one parent and one child 
    b) Multilevel inheritance - a chain of inheritance 
    c) Hierarchical inheritance - one parent multiple children 

27. Multiple Inheritance - No supported with class.
    class A{}
    class B{}
    class C extends A,B {} // this gives error

28. Constructors in inheritance - constructors are neither inherited not overridden only overloaded. 
    When a child object is created parent constructor runs first then child constructor runs.

29. super keyword - super() is used to call the immediate parent's constructor.
    Writing super() in child constructor is not mandatory. Java automatically inserts it.
    It is used to access parent class variable.

     class Parent {
         int x = 10;
     }
     
     class Child extends Parent {
         int x = 20;

         void display() {
             System.out.println(x);
             System.out.println(super.x);
         }
     }

     Inserting super is mandatory when parents does not have default constructor.

     class Parent {
         Parent(int x) {
             System.out.println(x);
         }
     }
     
     
     class Child extends Parent {
         Child() {
             super(10) // if it is not there then -> compilation error
             System.out.println("Child");
         }
     }

     In this case Java adds super() but there is Parent(int x ). So Java cannot initialize the parent

30. final keyword and inheritance - final class cannot be inherited.
    final class A{} // cannot be inherited.
    final method cannot be overridden 

    a child class cannot access private variables of parent .
    private methods are not inherited. 

31. Constructor execution order in inheritance - When an object of child class is created parent constructor executes first.
    Because child class contain parent part inside it. The parent must be initialized before the child part.

32. Method Overloading - Same method name but different parameters in same class.
    It is called compile time polymorphism.

     class Calculator {
          int add(int a, int b){
              return a+b;
          }

          int add(int a, int b, int c){
              return a+b+c;
          }
     }

     Rules of overloading - 
     a) only changing return type is not enough.
        int add(int a,int b)
        double add(int a,int b)

        It gives compilation error because parameters are same.

        This is valid -
          add(int,int)
          add(double,double)

33. Method Overriding - Child class provides new implementation of parent method. It required inheritance. 
    This is also run time polymorphism.

/////////////////////////////////////////// ENCAPSULATION ///////////////////////////////////////////

34.  Encapsulation is the process of combining data(variables) and functions that operate on that data into a single unit called class,
     while restricting the direct access to that data.

     Hide the data and allow access through methods.

     Example withoud Encapsulation : 

     class Student{
          String name;
          int age;
     }

     public class Main {
         public static void main(String[] args) {

             Student s = new Student();

             s.name = "Rahul";
             s.age = -20;
             System.out.println(s.age);
         }
     }

     Here anyone can set age and name. The data is not protected.

     Instead of making variable public make then private 
     then s.age = -20 gives error. Now age cannot accessed outside the class.

     We use getter and setter methods to access private variables. They also allow validation.

     class Student {

         private String name;  // only the same class can access private variables.
         private int age;

         public void setAge(int age) {
             this.age = age;
         }

         public int getAge() {
             return age;
         }
     }

     ------------------------------

     Student s = new Student();
     s.setAge(20);
     System.out.println(s.getAge());

     Getters : return the value
     Setters : update or change the value 


     Advantages of Encapsulation : 
     a) Date secruity
     b) Date validation 
     c) Better control 
     d) Easier maintainance 
     e) Flexibility 

/////////////////////////////////////////// POLYMORPHISM ///////////////////////////////////////////

35.  Polymorphism in Java is the ability of one method or object to perform different actions depending on how it is used.
     There are two types of polymorphism in java - 
     
     A) Compile time polymorphism ( Method Overloading ) - 
        Method overloading means methods have same name but different parameters.
     B) Run time polymorphism ( Method Overriding ) - 
        Method overriding happends when child class provides its own implementation of method inherited from parent class.

          @Override
          void sound() {
              System.out.println("Dog barks");
          }

          @Override tells the compiler - I intend to override a parent method.

          Rules of method overriding - 
          a) Method name and method parameters must be same.
          b) Return type must be same. 
          c) The child method cannot reduce the visibility of parent method ( public cannot become private ).
          d) final method cannot be overridden.
          e) static methods are hidden, not overridden.

36.  Upcasting - Upcasting means storing a child object into parent reference.
     Animal a = new Dog();
     This is safe, automatic, enables runtime polymorphism.

37.  Downcasting - This converts a parent reference back to child reference.
     Animal a = new Dog();
     Dog d = (Dog) a;

     It should be only done when the object is of child type.

     Polymorphism example - 

     Animal[] animals = {
          new Dog(),
          new Cat(),
          new Lion()
     };

     for (Animal animal : animals) {
          animal.sound();
     }

     Each objects responds with its own implementation.

41. Interface- An interface in Java is a blueprint that defines set of behaviour that a class must implement, without specifying how those 
    behaviour works. They dont have constructors.
    We use interface when unrelated classes need the same capability. We use classes when classes share code.
    Variables in interfaces are implicitely "public static final".

42. There are 3 types of interfaces - 
    a) Normal Interface - contain multiple interfaces.
    b) Functional Interface - contain exactly one interface method making it compatible with lambda expressions and functional programming.
    c) Marker Interface - Contain zero methods or constants. It simply marks or tags class to give it special instructions at runtime.

43. JIT - JIT is the main component of JRE that improves application performance by compiling Java bytecode into native machine code at runtime.

44. Bytecode - Bytecode is the intermediate, machine independent instruction set generated by Java compiler(javac) when it compiles Java

45. Multiple Inherintance - Multiple inheritance means one class inherits from more that one parent class.


    class A {
        void display() {
            System.out.println("A");
        }
    }
    
    class B {
        void display() {
            System.out.println("B");
        }
    }
    
    class C extends A, B {
    
    }

    Here C inherits from both A and B.

    Now imagine,

    C obj = new C();
    obj.display();

    There is ambiguity which class method should a Java call.
    This problem is resolved using interfaces - 

    interface A {
        void display();
    }

    interface B {
        void display();
    }

    class C implements A, B {

        @Override
        public void display() {
            System.out.println("Hello");
        }

    }

    When we implements two interface and both interfaces contain same method but in child class which implements these classes there is only one implementation for both the interfaces.

/////////////////////////////////////////// EXCEPTION HANDLING ///////////////////////////////////////////
46. Exception handling in java is a mechanism to handle runtime errors without terminating the application. It improves the reliability
    and maintainability of software by separating normal program logic from error-handling logic.

47. Exception - An exception is an event that occurs during the execution of a program that disrupts the normal flow of instructions.
    Exceptions mainly occur due to - 

    - dividing a number by zero
    - accessing an invalid array index 
    - accessing a null value 
    - file not found 
    - db connection failure 
    - invalid user input 

48. Hiearchy of Exceptions - 
                                            Object
                                              |
                                           Throwable
                                           /       \
                                        Error   Exception
                                                    |
                                            Runtime Exception
                                        
    a) Throwable - All exceptions in Java are derived from Throwable class. Root class of all exceptions and errors.
    b) Error - Represents serious system level problems. e.g. OutOfMemoryError, StackOverFlowError. Error should not generally handled in 
       application code.
    c) Exception - Represents conditions that application can catch and handle.
    d) Two types of exceptions - Checked & Unchecked exceptions.

        A) Checked Exceptions - checked during compilation. Must be handled using try-catch, throws like -> IOException,SQLException,ClassNotFoundException
        b) Unchecked Exceptions - Occur during runtime and derived from RuntimeException. Examples- NullPointerException, ArithmaticException,
           ArrayIndexOutOfBoundsException, NumberFormatException.

49. Java provides 5 keywords to handle exceptions - try,catch,finally,throw and throws.
    try block contain code that may produce an exception.
    catch block handles the exception.
    finally block always executed whether exception occurs or not. Used for cleanup operations.

    Multiple catch-blocks - 

    try {

    } catch (NullPointerException e) {
        System.out.println("Null Object");

    } catch (Exception e) {

    } finally {

    }
